# 设计原则

本文记录项目的交互、视觉与声音判断标准。公开页与后台共享“精确 / 有趣 / 克制”三条原则，但风格不同：公开页是纸质小刊物，后台是拟物控制台。文中数值以代码实现为准，代码变更时同步更新本文。

## 精确

直接操作要跟手。

- 鼠标悬停、点击、手指触摸的反馈立即出现，不等待动画。
- 状态变化优先使用瞬时切换，不用 transition 制造“顺滑感”。
- 颜色、边框、按压反馈默认瞬间完成。
- 加载和网络操作要给出明确状态，但不能用装饰动画拖延输入。

判断标准：用户做完动作后，界面应该在同一帧给出回应。

## 有趣

只有在有叙事价值的时刻才使用动画和声音。

例子：

- 切换频道时的 CRT 换台；
- 取消投稿时的碎纸机；
- 撕纸胶带：每截纸胶带都能撕，撕开时弹出系统“存储为”对话框，存储才让相片掉下去，取消就把胶带贴回去；松动的那截只是吸引锚；
- 贴纸胶带：每次贴胶带都有一只 🤚 横扫抹平，贴好后停 382ms 手才出现，出现后停 382ms 再划过，划完停 382ms 再放手；
- 致命错误后的关闭荧幕效果；
- 关键弹层的转场。

这些效果是例外，不是默认配置。一个动画如果只是让页面“看起来更高级”，就不加。完整清单见“叙事时刻”。

## 克制

少即是多。

- 如非必要，不做装饰性动画。
- 如果瞬时状态已经足够，就不加动画。
- 如果没有比“精确”更好的方案，就不加动画。
- 尽可能不引入第三方动画库。
- 不为了“顺滑”给普通按钮、链接、表单加过渡。

一个交互只保留必要的反馈；能删就删，能瞬时就不渐变。

当前的 `motion` 与 `three` 是为碎纸机这一叙事时刻不得已引入的：`three` 负责碎纸条的 WebGL 场景，`motion` 只用了 `useReducedMotion`。两者只允许在碎纸机组件内使用，不扩散到其他组件，也不作为新增动效的理由。

## 叙事时刻

以下是已经批准的叙事时刻。新增一项前先过“决策清单”。

### CRT 换台

切换 `/explore`、`/behind`、`/member/<id>`、`/staff`、`/admin` 频道，以及进入、离开取消投稿时触发（`ChannelTransition`）。

- 换台层持续 900ms：半透明黑屏、180×110 的灰度噪点和彩色马赛克每 55ms 重绘一次、扫描线、滚动亮带、两次白闪；最后 14% 淡出。
- 换台期间页面每帧随机抖动，位移为视口宽高的 30%–70%，并叠加 `contrast(1.08) saturate(1.15)`。900ms 结束时切到新频道并复位。
- 频道 OSD 显示 3000ms，例如 `CH. Explore`：左上角 64px、字重 900 的白字黑描边；宽度不超过 640px 时不显示。
- 切换完成后，一条白色余辉扫描线从视口 30–60vh 的随机位置向下扫过 30vh，持续 2400ms。
- 同时播放换台音效，见“声音”。
- 换台只藏不卸（`PublicRoot` 的 `ChannelStage`）：频道第一次换台进来才挂载，之后一直留着，离开时用 React 的 `<Activity mode="hidden">` 藏起来。藏起来时 `display: none`、effect 全部清理（计时器、rAF、监听都停），组件状态和 DOM 保留；换回来时 effect 重新跑，页面是离开时的样子（展开的成员页、排序、已叠好的相片、后台面板等）。
  - 每个舞台读的路由是冻结的：本频道是当前路由时读当前的，离开后一直读离开时那一条。否则藏起来的页面会读到别的频道的路由（比如成员页读到 `/explore` 会把自己渲染成跳转），状态照样丢。
  - 滚动位置按频道记，换回来在绘制前还原；第一次来，或路由变了（比如 `/member/3` 换成 `/member/5`，成员本子会按成员 id 重新开），回到顶部。
  - 例外：碎纸机页（`/explore/cancelSubmission`）仍跟着 Explore 的显示走，离开 Explore 就卸掉；System Reports 每次离开 Behind 都会卸掉，回来再晚 500ms 挂上（首帧太重，移动端会卡一下，见 `BehindApp.tsx` 的说明）：`PublicRoot` 给 `BehindApp` 传 `thisIsDisplay={activeChannel === 'behind'}`，卡片的渲染条件带上它（藏起来的子树里 effect 不会再跑，不能只靠 effect 卸载），effect 清理时把计时状态复位，回来那一帧卡片不会跟页面一起挂上。
  - 页面里的 effect 必须经得起“清理后再跑一遍”：挂载时只该做一次的事要自己用 ref 记下是不是已经做过。已经这样处理的：后台读 AdminPool（回来时静默重读）；剧本里“是，取消掉吧”和碎纸机测试跳进 `/explore/cancelSubmission`（只跳一次，否则从成员页等频道回到 Explore 时会带着已删的相片再进一次碎纸机）。

### 碎纸机

取消投稿页（`/explore/cancelSubmission`）用 `PaperShredder` 把成员的投稿碎掉。送进去的是那张投稿的 PhotoCard（宽 320px、摆正、不贴纸胶带，和确认页上的同一张），由碎纸机光栅化成纸条纹理。Safari（含 iOS 上所有浏览器，都是 WebKit）例外：整张卡片走 html-to-image 光栅化会得到白纸条，所以按 UA 判断后改送单张缩略图 `<img>`，碎纸机直接拿已解码的图片当纹理（`utils/browser.ts` 的 `isWebKitSafari`）。

- 页面出现 2000ms 后自动开始；也可以直接拖动纸张送入。
- 送纸速度为 35px/s，切成 30 条；碎纸条在 three.js 场景中落进浅仓，折叠堆叠在可见区域。没有 WebGL 时纸张照常送入，只是看不到出纸。
- 取消投稿请求在进入页面时就发出，不等动画；碎完后等待请求完成，再过 2000ms 回到 `/explore`。
- 马达和切纸声随马达启停，见“声音”。

### 致命错误 CRT

`FailureLayoutContainer` 收到错误后（来源：根组件渲染异常，或 `signal_critical_error`，例如公开页获取相册数据失败）：

- 等待 1000ms，原页面执行 550ms 的关屏：先压成一条亮线，再缩成一点，最高亮度为 50 倍，背景变黑。
- 再等 1500ms，错误页执行 4s 的开屏：先过曝闪动，再从黑场恢复。
- 错误页使用 guanzhi 8×8 点阵字体，带 0.15s 的闪烁和 1.6s 的 RGB 偏移文字阴影。完整字体下载期间，每秒多显示一个 `◼`（最多 7 个），字体加载失败时回退到原始字体地址，保证错误信息可见。

### 逐字文案

投稿剧本（`Submission`）的叙事文字逐字出现。

- 每个字间隔 42ms，每出现一个字播放一次逐字音效。
- 多个选项依次播放：后一个选项在前一个播完后，再等 420ms（10 个字的时间）开始。
- 首屏文案没有用户手势，浏览器还不能可靠地播放声音，因此首屏的文案和选项全部瞬时显示。
- 删除线等剧本节点可以单独触发一次音效作为节拍。

### 活动期相册的顺序

公开页里活动期（`in_event`，投稿期和投票期都算）的相册乱序展示，不按 `index`；往期相册和后台照旧。每次打开页面洗一次牌（`pool/view.ts` 的 `shufflePhotosForEvent`，按相片 id 和本次的随机种子算哈希排序），之后换台回来、SSE 推来更新，同一张相片的先后都不变；刷新页面才重洗。新相片照下面的规则插到最矮那列顶部，已有的相片不挪位。

### 新相片贴上瀑布流

由数据变化驱动，不看是谁、从哪里加的：SSE 推来的相册数据里多出一张相片，公开页（`Gallery`）和后台（`AdminGallery`）的瀑布流就把它贴上来（`components/Gallery/usePhotoPresence.ts` 比较这一次和上一次的相片列表）。自己投的稿不立刻贴：点击提交时先打开公开页 SSE 应用阻塞，上传和提交成功后切到“大感谢”，再等 2000ms 才释放；EventSource 连接始终不断，阻塞期间只缓存最新的 photos / members，释放后一次性合并。上传或提交失败时立即释放。

- 第一次拿到列表不播；后台相册收起时不记差异，展开那一刻已有的相片也不播。修改投稿（id 不变）不播。
- 后台瀑布流和公开页一样保留位置：新增的相片插到最矮那列顶部，删掉的由同列下面的顶上去；只有换了排序方式（Waterfall 的 `layoutKey` 变了）才按新顺序整体重排。所以新相片在下次换排序或重新展开之前不在它按排序该在的位置，票数变了也不会自动重排。
- 0–420ms：新相片插到当前最矮那一列的顶部（而不是追加到底部），那一列的 `top` 带 420ms 过渡往下挪出空位；平时瀑布流排布仍是瞬时的。
- 420–720ms：停顿 300ms，空位先露出来。
- 720–1620ms：相片用 900ms 慢慢落下，`translateY(-10px) → 0`、`opacity 0 → 1`；同时 3D 地以上沿为轴，从 `perspective(900px) translateZ(28px) rotateX(16deg)` 压平到墙面，阴影从远、大、淡收到静态阴影，像把相片按到墙上。相片的倾角从第一帧起就是最终值（入场动画在外层，倾斜在卡片自身）。
- 1620ms 起：贴纸胶带（见下面“贴纸胶带”），到 4146ms 放手为止。

### 相片从瀑布流撕下去

同样由数据变化驱动：SSE 推来的相册数据里少了一张相片（取消投稿、后台删除都一样），公开页和后台的瀑布流把它留在原位播完再拿掉。

- 0–180ms：纸胶带从粘着的左端撕起、消失（同“撕纸胶带”的撕开）。
- 180–562ms：停 382ms。
- 562–882ms：相片自身下移 24px、淡出，320ms，`cubic-bezier(0.5, 0, 0.8, 0.4)`。播放期间相片不能点、磁粒不能动。
- 882–1264ms：再停 382ms，这一格空着、位置还占着。
- 1264ms 起：这一格从列表里拿掉，同一列下面的相片带 420ms `top` 过渡往上顶。
- 遵循减少动态效果偏好时，直接拿掉、不过渡。

### 贴纸胶带

新相片贴上瀑布流、复印后贴回原件、取消保存后贴回，三处都是同一套：

- 0–380ms：纸胶带从上方 10px、离墙 36px、多转 7°、向前翻 28° 的位置落下贴平，停在该相片自己的随机位置和倾角上。
- 380–762ms：胶带贴好后先停 382ms。
- 762–982ms：一只 🤚（> 900px 为 28px，≤ 900px 为 25px，带一点投影）出现在胶带左端：从下方 8px 上移、淡入。手的框与纸胶带同位置、同宽、同倾角。
- 982–1364ms：按着停 382ms。
- 1364–1924ms：沿胶带方向从左端划到右端，560ms，`cubic-bezier(0.65, 0, 0.35, 1)`（起步和收尾都轻，中段匀快，像手掌抹过去）。
- 1924–2306ms：按在右端停 382ms。
- 2306–2526ms：放手：下移 8px、淡出。
- 放着磁粒时，放手之后磁粒才落回原位。减少动态效果时不显示手。
- 遵循减少动态效果偏好时，不过渡、不播入场，直接出现。

### 撕纸胶带

公开页每一截纸胶带都能点：看起来和平常一样，只是指针变成手形，点击区向四周扩大 10px / 6px。正在贴上去（新相片、贴回中）或正在撕下去的胶带不能点；系统对话框同一时间只开一个，开着时点别的胶带不理。

吸引锚只给公开页最上面那个相册（有活动相册时是它，否则是第一个过往相册），后面的瀑布流没有，只发生一次：

- 不计时：相册瀑布流第一次排好的那一刻（`Waterfall` 的 `onWatterfallRefreshed`），从最上面一排（各列第一张，格子上沿同高）里随机挑一张（正在贴上来的新相片除外），它的纸胶带一出现就是松的，没有“松开”的过程和过渡。只挑一次，之后重新排布（改窗口宽度等）不会换。左端还粘着，整体多转 5°，右端以 `perspective(240px) rotateY(-26deg)` 离墙翘起，投下一道小影子。它和别的胶带一样能撕，松动只是提示这里能点。
- 点纸胶带：先撕开，从它当前的样子（贴着或松动）开始撕。相片上放着登录成员自己的磁粒时，先用 200ms 把磁粒取下来、悬在原处上方（`translate(-2px, -10px) scale(1.12)`，影子拉远；磁粒在卡片右下角、不在 `.cover-area` 里，抬起不会被裁掉）；然后纸胶带从粘着的左端被撕起、消失（180ms）。
- 同一次点击里弹出系统自带的“存储为”对话框（`showSaveFilePicker`，建议文件名为 `src`）。动画停在撕开的样子，等对话框的结果，期间磁粒不能点。只有 Chromium 系（Chrome / Edge 等）在安全上下文里能拿到“存储 / 取消”的结果；Safari / Firefox 没有这个接口，网页也拿不到 `<a download>` 对话框的结果，这些浏览器会等完整复印动画播放完再下载（`src_url`，文件名为 `src`；跨域时改为新标签页打开）。
- 点“存储”：动画继续，原图在后台取回写进选好的文件；取不到（跨域没开 CORS 等）就改为新标签页打开原图。不管有没有磁粒，都统一复印一张掉下去，原件始终留在原处：
  - 0–380ms：一道偏冷的白光带（`mix-blend-mode: screen`）从上到下扫过整张卡片。
  - 380–640ms：复印件从原件上揭起来（朝屏幕抬 30px、往右下错开 3px / 4px、比原件亮 12%，原件还在墙上，所以看得出“多了一张”），随后同样直直掉下去（1000ms）；复印件上没有磁粒。
  - 1000ms 起：纸胶带重新贴回原件（见“贴纸胶带”，含手抹，到 3526ms 放手）；有磁粒时，放手后磁粒再落回原位 220ms，最后轻压到 0.94 再回到 1。复印期间磁粒由固定顶层单独承载，z-index 高于掉落的复印件，不会被复印件盖住。
- 点“取消”：不下载，动画停在这里，纸胶带重新贴好（见“贴纸胶带”，含手抹，2526ms）。贴回来的是普通的胶带，不是松动的样子，之后也不会再松。放着磁粒时，放手后磁粒再落回原位（220ms）。
- 遵循减少动态效果偏好时，撕开不播动画、直接等对话框；“存储”后原件保持不动，不播放复印和掉落；Safari / Firefox 没有对话框时动画已瞬间完成，直接下载；“取消”直接恢复成贴好的胶带。

### 弹层转场

确认投票等关键弹层使用 `DialogLayout`。

- 进入：遮罩在 800ms 内加深到 `rgba(0, 0, 0, 0.182)`；横贯屏幕的白色版面同时从左侧滑入，边缘带 20px 渐隐；内容延迟 300ms 后用 500ms 从左侧 1em 处淡入。
- 退出：白色版面在 800ms 内向右滑出，内容在 500ms 内向右 1em 淡出。
- 组件按 1100ms 切换状态；打开期间禁止页面滚动。

## 声音

声音的用意类似 Nintendo Switch 的系统音效：

- 有趣：耳朵上的愉悦感，让按键、换台、出字这些动作有“质感”。
- 精确：声音和动作在同一时刻发生，是即时反馈，不是背景音乐，也不延迟操作。

### 合成方式

- 全部用 Web Audio 实时合成，没有音频文件，也不引入音频依赖。
- 素材只有振荡器（三角波、方波、锯齿波）、白噪声缓冲和滤波器；每个音效都由短包络塑形，用完即停。
- 音效与动作绑定，不做循环背景音。唯一的持续声是碎纸机马达，它只在马达运转时响。

### 预热时机

- 浏览器只允许在用户手势之后启动音频。`PublicRoot` 在首次 `pointerdown` 或 `keydown`（capture，只触发一次）时预热换台和逐字两个音频上下文。
- Spinner 在需要出声时监听 `pointerdown` / `keydown` 来恢复自己的音频上下文，卸载时关闭。
- 碎纸机的马达在首次需要出声时才创建。
- 正因为首屏没有手势，投稿剧本的第一面整体瞬时显示，不播放逐字音效。

### 降级规则

- 没有 `AudioContext`、创建失败或播放抛错时，一律静默，不影响动画和操作。
- 逐字音效和 Spinner 滴答在音频上下文不是 `running` 状态时直接跳过，不排队补播，避免恢复后一连串集中爆发。
- 换台、琴键、盖板、发射按钮这类单次音效在 `suspended` 状态下会先尝试恢复，恢复后再播放；恢复失败就放弃。
- 组件可以关闭声音：Spinner 的 `audioVolume={0}`、碎纸机的 `sound={false}`。

### 音量层次

从响到轻：

1. 换台：主增益 1.28，“噗”的峰值 0.62。它标志频道切换，是最响的一声。
2. 发射按钮与盖板：“dang”撞底峰值 0.45，金属分音 0.2 / 0.08 / 0.04；盖板撞限位峰值 0.32。只在图片重建这一次性操作时出现。
3. 琴键：按下时键体峰值 0.42；45ms 后旧键回弹，主增益 0.88，峰值 0.15。
4. Spinner 滴答：`audioVolume` 乘以 0.55，常用的 0.8 对应峰值约 0.44，但只持续 30ms。
5. 碎纸机马达：持续输出 0.16，启动时间常数 30ms，停止时间常数 90ms。持续声必须压低。
6. 逐字：峰值 0.09，34ms。它出现得最频繁，所以最轻。

原则：越频繁、越持续的声音越轻；越少见、越有转折意义的声音越响。

## 查看大图

- 保持点击缩略图打开、点击大图或背景关闭；也可用 Escape 关闭。
- 保持原适屏尺寸和居中规则，以及图片 382ms、背景遮罩 618ms 的转场时长；转场只改变 transform 和 opacity，不逐帧修改尺寸或位置。
- 双指捏合、trackpad 捏合、鼠标滚轮都按手势/鼠标位置中心缩放，范围是适屏大小的 1–5 倍。trackpad 捏合继续支持 Chromium/Firefox 的 ctrl-wheel 和 Safari 的原生 gesture 事件；鼠标滚轮使用普通 wheel 事件。两者都不缩放整个网页。
- 鼠标滚轮和 trackpad 双指滚动按 `ctrlKey`、`deltaMode`、`deltaX` 和 legacy `wheelDeltaY` 区分：`deltaMode !== 0` 视为鼠标；`deltaX !== 0` 视为 trackpad；有 `wheelDeltaY` 时以 `% 120 === 0` 判断鼠标；没有 legacy 值时只有纯纵向整数大 delta（≥50）作为鼠标兜底。带水平分量或小步进的 trackpad 双指滚动继续平移，不把双指平移误判成鼠标缩放。
- 放大后单指、鼠标或触控笔拖动平移，trackpad 双指滚动也可平移；平移约束在图片边界内。双指操作结束或只剩一指时，不把松指误判为关闭。
- 未放大时，单指向上或向下拖动超过 100px，且纵向位移大于横向位移，松手关闭；不足阈值则立即复位。点击允许 8px 内的触摸抖动。
- 缩略图点击回调内立即下载 optimized 字节，不排队等待入场动画。图片和背景入场动画全部结束前，只显示缩略图，不解码或挂载 optimized 图片；结束后异步解码并直接插入已解码的图片元素。
- 关闭或切换相片时取消旧请求，忽略迟到的解码结果；退出完成后释放对象 URL 和事件监听。加载失败仍保留缩略图并提供重试。
- 瀑布流里的相片是斜贴的：点击时上报相片（不含拍立得白边）未旋转的矩形和倾角。入场时大图从这个倾角出发，一边放大一边转正；退出时倒回到原来的倾角和位置。两头的 transform 用同一串函数（translate3d → rotate → scale），浏览器逐项插值。
- 横长图在卡片里是转 90° 竖着贴的：点击时上报的是那张躺着的原图（宽高对调，倾角 = 卡片倾角 + 90°）。入场时一边放大一边转回横向，大图是横向原图；退出时倒回去，躺回卡片里。
- 遵循减少动态效果偏好时，转场时长为 0；不新增运行时依赖。

## 相片卡片 PhotoCard

公开页与后台的瀑布流共用同一个 `PhotoCard`（原 PhotoBox），所见即所得，同一张相片在两边的大小、倾角、位移完全一致。

- **拍立得**：四周白边为卡片宽度的 4.5%（6～12px），相片下方留白不小于白边的 4.5 倍（至少 48px），写 28px 小圆头像、昵称和描述（compact 的排列方式）。顶边贴一截纸胶带（与名单簿拼贴相片的同一种：宽 40%、高 17px、半透明米黄、两侧虚线），按相片 id 随机 `translateX(-55%～-45%) rotate(-3°～3°)`。
- **写字区的有无**：非活动的相片（以及后台）带作者，下方总有写字区，没有描述也要放头像和昵称；活动中的公开相片不显示作者，没有描述时就没有写字区（不渲染 `.bottom-area`），下方只留与四周同宽的白边，有描述时只写描述。不再有心形投票条，也没有 normal / compact 两种卡片之分。
- **随手贴上去**：大小、倾角、横向位移、纵向错落全部由相片 id 决定（不用随机数），刷新、缩放窗口、换列数都不变。倾角 ±0.8°～3°；竖长的卡片尽量摆正，“竖长”看整张卡片（相片竖长、横长图转过来、描述字多或回车多把写字区撑高都算，描述行数按换行和字宽估算，见 [images.md](images.md)“卡片高度估算”）：卡片高宽比 ≤ 1.4 时倾角不变，≥ 2.4 时只留 ±0.3°，中间线性过渡，倾斜方向不变（同样的倾角，卡片越高底边横移越多，像要滑下来）；卡片宽为列宽的 84%～100%，≤ 900px 为 78%～92%，≤ 640px 的双列为 92%～100%；纵向错落 0～24px，≤ 900px 为 0～12px。都是静态摆放，没有动画。
- **横长图竖着贴**：宽 ÷ 高 ≥ 2 的相片（`SIDEWAYS_RATIO`），在拍立得里顺时针转 90° 竖着放，原图顶边朝右；16:9 这类普通宽图不转。纯前端显示：不重新生成图片、不改 storage、不经过 canvas（Safari 把 AVIF 画进 canvas 会出白图）。转过之后就是竖长卡片，按上一条自动摆正。超长横条不裁，照原比例显示（10:1 的图在 230px 列宽下相片约 2100px 高）。点开大图时恢复横向原图，见“查看大图”。实现约束见下方“横长图竖贴的实现约束”。
- **不碰撞**：卡片转过之后的外接框，横向不越过“本列 + 两侧各半个列间距”，放不下就把卡片缩小，不减小倾角；横向位移最多越过列边四分之一个列间距。纸胶带探出的高度、倾斜多出来的上下高度、纵向错落都写进瀑布流格子的上下留白，参与排布。列间距：> 900px 为 32px（> 1535px 的自动列数保持 27px），≤ 900px 为 20px。
- 后台 `.admin-gallery` 最大宽度 1400px，布局按 1535px 封顶，不进入公开页 >1535px 的自动列数分支；公开页仍按真实视口自动加列。
- **双列（≤ 640px）尽量放大**：小屏上相片太小，所以只有双列时收窄留白、放大卡片：瀑布流左右留白 8px（其他断点是 20px）、列间距 10px，卡片宽为列宽的 92%～100%。外侧那一列斜过去时最多越过瀑布流边缘 5px（半个列间距），伸进左右留白但不出屏幕。上下间距、纵向错落不变。375px 宽的手机上卡片平均宽从约 134px 变成约 167px（面积约 1.5 倍）。常量是 `Gallery/index.tsx` 的 `DUO_SIDE` / `DUO_GUTTER`，卡片比例在 `scatter.ts` 的 `duo` 分支。
- 瀑布流只量外层格子；倾角和横向位移是卡片自身的 transform，相片里的磁粒、后台的编辑入口都在卡片里，跟着一起斜。
- **描述用手写字体**：13px，字体栈为 Bradley Hand / Segoe Print（西文）→ 霞鹜文楷 → 行楷（Xingkai SC / STXingkai）→ 楷体（Kaiti SC / STKaiti / KaiTi / BiauKai）→ PingFang SC / Microsoft YaHei → sans-serif，不下载网络字体。定义在 `.photo-card` 的 `--photo-card-hand` 变量上。
- **相纸外壳 `PhotoCardPaper`**：白边、阴影、倾斜和纸胶带抽成 `PhotoCardPaper`，`PhotoCard` 和投稿表单共用。纸胶带的位置写成 `--tape-x` / `--tape-r` 两个变量，入场“贴胶带”的动画沿用同一个位置。
- **成员自己的投稿**：“你这不是已经投稿了吗？”、取消投稿确认页、碎纸机里都用 `SubmittedPhotoCard`：宽 320px、摆正、不贴纸胶带的 PhotoCard，与投稿表单是同一张相纸。这些重复出现的卡片不挂 `id="photo-{id}"`（`anchor={false}`），相片加载优先级只认瀑布流里那一张。
- **投稿表单**：一张宽 320px、摆正、不贴纸胶带的拍立得。相片位就是选图按钮（没选图时 4:3，显示“点击此处选择作品，或者拖拽文件到此处”，选了图按原图比例显示预览）（横长图同样转 90° 竖着放，投稿时看到的就是贴上墙的样子），写字区就是介绍输入框（手写字体 16px，无边框，placeholder“点击此处填写介绍（可不填）”，随内容长高）。“提交”按钮不变。

### 横长图竖贴的实现约束

这是一个容易被后人无意破坏的技术特性，改相关代码前先读这里。前后端图片处理的整体思路见 [images.md](images.md)。

- **唯一的尺寸来源**：相片区域（`.cover-area`）的尺寸只能从 `src/web/components/PhotoCard/scatter.ts` 的 `photoCardCover()` 取。它对横长图返回转过之后竖着的框（`cover_height = cover_width × 宽 ÷ 高`）和 `sideways: true`。PhotoCard 渲染、瀑布流高度估算（`estimatePhotoCardHeight`）、防碰撞、竖长摆正、投稿表单、后台磁粒（`VoteMagnets` 的 `cover_width` / `cover_height`）都依赖它。任何地方自己拿 `photo.height / photo.width` 算相片高度，横长图就会与实际渲染对不上，瀑布流出现空隙或重叠。
- **旋转只在 `<img>` 上**：`.cover-area` 按竖框占位，不转；里面的 `<img>` 行内宽高对调成原图方向（`cover_height × cover_width`），由 `.cover-sideways`（投稿表单是 `.CoverImageSideways`）绝对定位居中后 `rotate(90deg)`。所以叠在 `.cover-area` 上的东西（后台磁粒、复印扫描光、加载失败提示）都按竖框排，不跟着转。`.cover-area` 必须保持 `position: relative; overflow: hidden`。
- **点开大图**：`PhotoCard` 的 `onClickCover` 对横长图上报宽高对调的矩形，倾角加 90°（`Detail/geometry.ts` 的 `thumbnailTransform` 原样使用）。改大图转场时别丢掉这 90°，否则第一帧会从一张被压扁的横图开始。
- **不经过 canvas**：别为了“省一次 transform”把横长图预先转成新图片（canvas / 服务端）。Safari 把 AVIF 缩略图画进 canvas 会出白图（碎纸机已经踩过）；服务端改图又会让 storage 和原图下载不一致。碎纸机在非 Safari 下用 html-to-image 光栅化整张卡片，会带上这个 CSS 旋转；Safari 回退送的是单张原图，不转，这是可以接受的。
- **只看宽高比**：判断条件是 `photoIsSideways()`（宽 ÷ 高 ≥ `SIDEWAYS_RATIO` = 2），不看 EXIF。宽高以 storage 记录的 `width` / `height` 为准；投稿表单里还没上传的图，以浏览器读出的尺寸为准。
- 后端缩略图的短边不低于 256px（见 configure.md“相片缩略图与 optimized 的尺寸规则”）：横长图按宽 640 缩会只剩一百来像素高，转过来竖贴后沿列宽方向就糊了，这条下限保住了它。别去掉。
- 单测 `test/unit/photo-card-scatter.test.ts` 覆盖阈值、竖框尺寸和转过之后几乎摆正；视觉效果没有自动测试。

## 公开页投票磁粒

- 投票期内，登录成员（已确认 QQ）只看得到自己的磁粒，不显示别人的。磁粒吸在整张卡片的右下角（`right: 4px; bottom: 4px`，不在 `cover-area` 里），直径 32px，是后台统计磁粒（16px）的两倍；点击区 40px。空位是一圈同尺寸的蓝色虚线，点一下放上一颗蓝色磁粒（投一票），再点一下收回。有磁粒时写字区的描述右侧让出 44px，文字不会写到磁粒底下。磁粒一律是蓝色，公开页没有“红色 = 5 票”。
- 放磁粒是托盘里的磁粒自己飞过去：点下去时先预热音频上下文，磁粒位保持空位，托盘里刚空出来的那一格（托盘从右往左用掉；“磁粒 × 剩余”时是那一颗）飞出一颗 `position: fixed` 的磁粒，沿抛物线落到卡片右下角的磁粒位：横向 ease-in-out，竖向先抛到比起点和终点都高 36～90px 的顶点（ease-out）再落下（ease-in），飞行 380～720ms（按距离），途中放大到 1.18 倍、影子拉远，像被拿起来。到达那一刻响一声“ta～”，随后 120ms 压扁（横 1.1、竖 0.86）、回圆并淡出，磁粒位换成真正的那颗。不限票数（“磁粒 × ♾️”）时磁粒不从托盘出发，而是从磁粒位正上方 88px 处落下（300ms，加速下落，70% 处磕到纸面并响“ta～”）。收回磁粒由一只 🤏（28px）来捏：它在磁粒右下方 16px / 18px 处就近淡入（140ms），凑到磁粒上（180ms），捏住（160ms，手收紧到 0.86，磁粒被捏得略扁），停 120ms，带着磁粒沿弧线飞回托盘里最左边的空位（280～560ms，按距离；磁粒放大到 1.12、影子拉远），放下（100ms），然后上移 18px 淡出（180ms）。这一票在磁粒落进托盘那一刻才真正收回，所以飞回去的途中托盘那一格仍是空位，卡片上那一格已是空位且不能点；同时收回几颗时依次往右放。“× 剩余”“× ♾️”时放回托盘上那一颗；托盘还没出现时放到它将要出现的屏幕底部居中处。收回不出声。遵循减少动态效果偏好时不飞、不落、不放音效，点了直接出现。
- 屏幕底部居中、`position: fixed; bottom: 15px` 是磁粒托盘（HUD）：托盘里的磁粒与卡片上的一样大（直径 32px，间距 10px，托盘高 48px）。一共能投几票就有几颗，放出去的位置留下虚线空位；一排最多画 10 颗，窄屏按宽度少画（两侧各留 15px，约 375px 宽的手机能画 8 颗），画不下时显示“磁粒 × 剩余颗数”；不限票数（`vote_limit = 0`）的相册显示“磁粒 × ♾️”。磁粒用完还想放时，托盘描红 600ms，瞬时出现、瞬时消失。
- 托盘在“可别忘了点下面的提交了，朋友”弹层（`ConfirmVote`）开着的时候不显示；点任意位置离开弹层后，等离场动画（1100ms）播完再过 2 秒才出现（瞬时，无过渡）。
- 提交投票后不能再放或收回；已经放上去的磁粒仍留在相片上（只读），托盘隐藏。托盘层级低于查看大图和各种弹层。
- 一颗都没选就点“提交”：不弹浏览器对话框，在按钮正下方出一行 13px 的红字“你需要选择至少一部作品才能提交投票”；选中任意一张相片后这行字自动消失，不打断操作。

## 后台相片投票磁粒

- 仅 `/admin` 的 PhotoCard 显示全部成员的投票磁粒（公开页只显示自己的，见上一节）；磁粒的样子由公开页与后台共用的 `components/Magnet` 提供；复用 AdminPool 的 `vote_records`，按相片归集，票数与记录使用同一份数据，不新增 API 或公开投票人信息。
- 蓝色 `rgba(48, 103, 133, 1)` 表示 1 票，红色 `#ba1616` 表示 5 票。每 5 票换成一颗红色，余数为蓝色；排列先蓝后红，高面额靠右，6 票为「蓝 红」，13 票为「蓝 蓝 蓝 红 红」，0 票不生成磁粒。
- 磁粒直径 16px、间距 6px，贴在相片右上方、距边缘 8px，满行后换行。空间不足时整体等比缩小；极短或极窄图片的留白不超过图片短边的 1/4。磁粒和“0 票”入口都在 `cover-area` 内，绝不进入 `bottom-area`，不改变瀑布流卡片尺寸。
- 每个展开且非空的相册在管理 `.panel` 与瀑布流之间显示图例一行：左边是“固化这个排序”按钮和排序控件（`SortSelect`，投稿时间 / 获票数 + 升降序箭头，默认投稿时间升序，同值按相片 ID 升序保持稳定），右边是 1 票、5 票磁粒。宽度 > 640px 时图例左对齐上方黄色相册卡片（≥ 1035px 左缘 82px；641–1034px 卡片通栏，对齐卡片内容左缘 18px），≤ 640px 居中。排序控件只重排当前页面的相片数组副本，不修改 AdminPool、不调用 mutation；每个相册各自记选项（不持久化，重新挂载回到默认）；瀑布流按输入顺序重新排布且保持相片组件挂载，不重置磁粒偏移。只有点“固化这个排序”弹出确认，确认后弹层立即关闭，才用 `adminSortPhotos` 一次把当前展示顺序写成相片 `index`，公开页按 `index` 展示、随之改变。进度写在按钮上：请求中显示“固化中…”并禁用，成功后显示“固化成功”2 秒，再瞬时回到“固化这个排序”；三种文案叠放在同一格，按钮宽度始终等于最宽文案，不跳动。请求失败直接触发 `signal_critical_error`（致命错误关闭荧幕），按钮回到“固化这个排序”。公开页瀑布流仍使用原有位置保留规则。原“按票数排序”按钮和接口已移除。
- 相片磁粒使用 `translate()` 添加 X 轴 1–2px、Y 轴 2–3px 的正向随机偏移，每颗磁粒在首次挂载时生成并由 `useRef` 缓存；普通重渲染及切换相片排序不重新生成。使用面额与该面额内序号作为稳定 key；极小图片留白不足 3px 时缩小偏移，避免越出图片区。图例磁粒不偏移。
- 点击磁粒组或“0 票”入口打开只读投票记录，显示总票数、投票人昵称、QQ 和投票时间，按时间从新到旧排列。找不到成员时仍保留记录与票数，并显示成员 ID。
- 记录列表内部滚动，支持键盘打开、Escape 或点击外部关闭；磁粒点击不触发相片编辑，弹层内部操作也不冒泡到卡片。沿用现有 Popover，不新增动效或依赖。

## 公开页的 UI 风格

回顾 `src/web/` 的公开页（`/explore`、`/behind`，不包含后台），整体风格可以概括为：

**纸质独立刊物 + 早期日式个人网站 + 早期 OS X 式轻拟物。**

它不是现代 SaaS 或通用相册模板，而是一个有性格的私人活动站点。具体表现为：

- **底色与背景**：全局底色是低饱和的蓝灰 `hsl(217deg 20% 80% / 50%)`，叠加 1px 宽的竖向细条纹（白 `rgba(255, 255, 255, 0.7)` 与灰 `rgba(220, 220, 220, 0.4)` 交替），即早期 OS X 的 pinstripe。iOS / iPadOS 去掉条纹，只留纯色。“纸”体现在白色的相片卡片和横贯版面的白色弹层上，而不是底色。
- **Behind 页**：白底、正文 `#252525`；深色模式下底色为 `#1b2027`。
  - 布局：< 800px 单列，从上到下是品牌、名单簿、System Reports。≥ 800px 分两行：第一行左品牌、右 System Reports，各 360px，竖向居中对齐；第二行名单簿横跨两栏，720px，与上面两块左右对齐。≥ 1600px 一行三栏，从左到右是品牌 360px、System Reports 360px、名单簿 720px，栏距 40px，三块竖向居中对齐（360 + 40 + 360 + 40 + 720 加左右留白 64 = 1584px）；名单簿在公开页最宽只画中等布局，720px 正好装下；System Reports 摆正（`ReportCard` 的 `config.angle = 0`，其他宽度保持默认 -1°）；System Reports 的 545px 预留高度照旧保留，卡片晚出现时这一行不会变高、旁边两块不会跳。System Reports 晚 500ms 才挂载，外壳常驻并预留 545px 高度，卡片出现时名单簿不往下跳。
  - 品牌图是相片堆叠（`BehindPhotoStack`），原型是旧站“网址迁移说明”页的 `#photos-container-wrapper`。观察角度跟布局断点（800px）走，有两种：≥ 800px 品牌与 System Reports 并排，改成正上方俯视，和 System Reports、名单簿一样是纸平放在桌上、从上往下看：没有 `rotateX`，只留平面内的 `rotateZ`；入场时在最终位置上先往上偏 30～60px、多转 -15°～+15°、透明，100ms 后回到 `translateY(0) rotate(0)`；上下层用 z-index（第几张）；相片长边 200px、偏移 ±20px、logo 176px，整叠落在 340×340 内，不伸进旁边的 System Reports；落影是相片堆底下一团径向渐变，略向下偏 10px。< 800px 单列的移动端视图保留原版斜看：容器 perspective 1024px、每层 `rotateX(45deg)` 躺倒，从 `translateZ(200px)` 透明处落到 `translateZ(第 n 张 px)`；相片长边 256px、偏移 ±30px、logo 256px；落影是原版躺倒的圆形、往左上投。两种角度共用 opacity 282ms、transform 882ms（ease，原版时长），叠放都是后放的压在上面。每张相片的倾角（rotateZ ±30°）、偏移方向、放大（1～1.1 倍）只随机一次，改窗口宽度跨过断点时同一叠直接换成另一种角度，不重新洗牌、不播过渡。编排：第一张是 `assets/torzo-logo.png`，摆正，垫在最底下；之后从 ClientPool 随机取 12 张相片缩略图（5px 白边）一张张叠上去。第一张落下 1s 后落影淡入。页面真正显示（换台结束）1s 后开始，每张至少间隔 3.5～4s；加载失败或 18s 超时的相片跳过。系统开启“减少动态效果”时直接全部摆好。400px 以内整叠缩到 85%。每次进 Behind 重新洗牌。
  - 后台入口：Navigator 右上角、换台按钮左边的“A”圆按钮（与换台按钮同为 34 / 28px 的 `PushButton`，按钮面印字），点了直接换台到 `/admin`，登录在后台里做。“A”用 `.navigator-title-admin-word` 同一套 Impact 斜体，颜色压暗到 `rgb(122 40 96)` 以配米白按钮面，下沿一道白、上沿一道暗，像丝印；按下时再暗一档。页面里不再放登录表单。
- **色彩**：低饱和蓝绿主色 `#306785`，少量红心点缀。颜色数量少，对比克制，主要靠留白和层次，而不是高饱和配色。
- **排版**：大留白、窄内容列、居中叙事、细分割线、超大标题。照片以错落卡片/瀑布流的方式排列，有编辑排版感，不是整齐划一的网格。
- **相片卡片**：拍立得 `PhotoCard`，顶边一截纸胶带，在瀑布流里按相片 id 斜贴、错落；下方留白写头像、昵称和描述；投票是放磁粒（见“相片卡片 PhotoCard”“公开页投票磁粒”）。
- **组件质感**：按钮有轻微拟物的高光、渐变、内阴影和按压下沉；圆形环按钮、胶囊按钮、细线输入框。拟物是轻的，不追求写实材质。
- **文字**：正文以系统无衬线字体为主，复古感来自排版和组件，而不是全局使用像素字体。文案口语化、朋友式，带轻微戏谑或日式翻译腔；关键提示使用大字号和横贯版面的标题。
- **特殊时刻**：CRT 换台、碎纸机、致命错误 CRT、逐字文案、新相片贴上瀑布流、相片撕下去、贴纸胶带、撕纸胶带、弹层转场，详见“叙事时刻”。
- **动效**：数量少，基本只服务于叙事和状态转折。普通悬停、点击和状态切换依赖瞬时反馈。

这套风格的核心不是“复古元素堆叠”，而是：像一本有人味的纸质小刊物，而不是一个产品化后台。

## 后台的 UI 风格

`/admin` 是**拟物控制台**：把管理工作做成一台有按键、指示灯、显示屏和打印机的操作台。它对应的是“有趣”——管理本身也可以好玩。

- **基础**：所见即所得编辑器，复用公开页的 Navigator、照片卡片、圆角、pinstripe 底色和轻拟物语言，管理者看到的就是公开页的样子。
- **琴键**：面板切换是一排录音机式琴键（`role="radiogroup"`）。按下的键立即切换面板，旧键同时弹起，并配按下声和 45ms 后的回弹声；方向键可以切换。大屏时所有面板平铺，琴键只负责定位。
- **门禁（登录）**：每次打开或刷新页面后第一次进 `/admin` 都先过门禁，本地已有 token 也一样。同一次打开里过了门禁、换台离开再回来，后台页是保留着的（见“CRT 换台”的“只藏不卸”），直接回到控制台、不再过门禁，并在后台静默重读一次 AdminPool（不切回“正在读取”）；这次重读遇到 token 失效，照常回到门禁报警。门禁通过之前，`/admin` 只显示 Navigator 和控制台外壳（`AdminConsoleShell`）：琴键照常摆着但一个都不按下、不可按，主面板里是一台门禁机（`AccessPanel`）：四角螺丝的拉丝铝面板，压印铭牌 `ACCESS CONTROL` / `ONLY ADMIN`，绿色液晶屏写状态和提示，下面是密码框 + “开锁”键，底部喇叭孔和“核对”（琥珀）、“拒绝”（红）两颗灯。喇叭孔与右边灯组（含字）等长：宽度运行时量灯组得到，孔横向均匀铺开，不出现半个孔。
  - 液晶屏字体是 `guanzhi 8x8 base`（`index.html` 内联的子集），屏上的字只用 A-Z、a-z、0-9 和空格，不写中文和标点。状态行 32px、提示行 16px，保持点阵整数倍（字体 1/16em 一个像素，16px 时 1 像素 = 1px）。
  - 屏上文案：`Locked` / `ENTER PASSWORD...`；核对本地 token 时 `VERIFYING` / `CHECKING TOKEN`；密码登录时 `VERIFYING` / `PLEASE WAIT`；本地 token 被拒时 `INVALID TOKEN` 或 `EXPIRED TOKEN`（反白，闪法同 `ACCESS DENIED`）/ `ENTER PASSWORD...`；`ACCESS DENIED`（反白，立刻闪 3 次：灭 180ms、亮 220ms，闪完常亮；连续被拒每次都重新闪）/ 原因；`LOGIN SUCCESS` 或 `IS LOGINED` / `WELCOME`。服务端报错是中文，前端按状态码换成英文：401 `WRONG PASSWORD`、429 `TOO MANY TRIES`、连不上 `NO CONNECTION`、其他 `ERROR <状态码>`；空密码是 `ENTER PASSWORD`。
  - 等待输入（`Locked`，以及 token 被拒之后）时 `ENTER PASSWORD` 后面的点照 `index.html` 的 Loading 做法：每 382ms 加一个，加到第 8 个时清空，屏上循环显示 1～7 个、0 个。离开等待状态就清零。
  - 点不是字符：字体里没有半角 `.`，`。` 又是全角太宽，所以每个点是一个 SVG（`LcdDot`）：宽 0.5em（半角字宽）、高 1.25em（= 提示行 line-height）、`vertical-align: top` 占满整行，2×2 字体像素的方点画在 SVG 正中，所以点落在行高的垂直中线上、水平也居中，不贴行底。改提示行字号或 line-height 时 `.lcdDot` 和 viewBox 要一起改。
  - 本地已有 token：门禁一出现就锁住输入框，向 `GET /auth/check` 核对（只验 token，不读后台数据）。通过 → 走和密码登录完全一样的成功流程，只是写 `IS LOGINED`；`401`（过期）→ `EXPIRED TOKEN`，`403`（签名不对、不是 JWT、不是 admin）→ `INVALID TOKEN`，两种都清掉本地 token、响报警声，等待重新输入密码；连不上等其他错误 → `ACCESS DENIED` / `NO CONNECTION` 等，token 留着，可以直接输密码。
  - 用着用着后台请求被 401 / token 类 403 拒绝时，丢掉已读数据回到门禁，一进来就报警并显示 `EXPIRED TOKEN` / `INVALID TOKEN`。
  - 声音：密码框每输入或删除一次“哔”一声；密码被拒时两声低沉蜂鸣；token 无效 / 过期时高低交替的报警；通过时两声上行“哔—哔”。直接打开或刷新 `/admin` 时页面还没有用户手势，浏览器不让出声，核对 token 的成功音 / 报警会静音（闪烁照常）；从“A”按钮换台进来有手势，能响。
  - 通过后不立刻进去：放成功音（260ms），然后 `LOGIN SUCCESS` / `IS LOGINED` 闪 3 次（灭 180ms、亮 220ms），常亮再停 240ms，共约 1.7s 后才进入管理界面；期间密码框和开锁键锁住。门禁的动效只有这三处（等待的点、拒绝类闪烁、通过类闪烁），其余状态变化都是瞬时的。登录前不发任何后台请求、不挂任何需要后台数据的面板。
- **“登录”灯**：琴键组右侧一颗 `LedIndicator`，标签“登录”：未登录黄灯，已登录绿灯（包括登录后读取 AdminPool 期间）。大屏（≥ 641px）琴键组隐藏时，这颗灯跟着一起隐藏，改到 Navigator 里显示：在“换台”按钮左边、与按钮之间多空 4px（Navigator 的 `indicator` 灯位），颜色规则不变。640px 以内反过来，Navigator 里不显示。任何宽度下屏上只有一颗“登录”灯。
- **指示灯**：LED 有常亮和脉冲两种模式。常亮模式切换用 150ms；脉冲先保持高亮，再按 RC 放电曲线衰减。
- **热敏打印机**：只有出错才吐纸。纸是平的，从槽口直接伸出，不做弯曲和透视；新的一行贴着槽口，用 240ms、6 级阶梯推进，把旧行往下推，最多 14 行。
- **玻璃盖**：危险操作罩在玻璃盖下。点一次盖板就弹开（340ms 回弹曲线，`rotateX(-108deg)`）并配盖板弹出声，再点一次合上；开盖后红色按钮才可按，按下时配“dang”声。按下的同一帧“剩余项目”数码管就显示总数，不等第一张图处理完；重建结束后盖板自动合上。
- **按钮与材质**：银白塑料按钮、内凹面板、磨砂指扣，比公开页更“硬件”，但仍然不追求照片级写实。
- **名单簿（线圈本）**：顶部线圈穿过纸页的孔，纸面是 27px 横线和左侧 44px 处的红色页边线，底下压着两张纸。名单不滚动而是分页：行高 54px，每页行数 = floor((本子高度 − 122) / 54)。名单页页眉左边是“名单簿（共 X 人）”，右边是排序控件和“+”新增按钮（与左上角放大镜按钮同尺寸 24×22px、同 13px 图标），不另放人数标签。排序控件（`SortSelect`，与相册里投票磁粒图例的相片排序共用）是一个外壳：左边箭头按钮（↑ 升序 / ↓ 降序，点击即换向，无过渡），一道刻线，右边原生 select。名单可按昵称、member_id、创建时间、投稿数量、投票数量排序，默认创建时间升序；主键相同时按 member_id。换排序回到第 1 页，不播翻页。点成员或“+”翻到成员页（二级页面），表单就写在纸上，下方是一张拼贴卡，小标题写“过去的投稿（共 X 张）”（新增成员时只写“过去的投稿”）。QQ 号输入框是 `type=number`，只接受 0～9，隐藏上下箭头。
  - 手写体：表单、搜索框、小标题、拼贴说明用同一组手写字体 `--hand`：手札体（Hannotate SC）→ 翩翩体（HanziPen SC）→ 楷体（Kaiti SC / STKaiti / KaiTi / 標楷體 / AR PL UKai）→ Segoe Print / Bradley Hand → cursive。不打包字体文件。
  - 页眉左列：页眉最左边的小按钮（名单页的放大镜、成员页和续页的“‹”返回）放在页边线左侧 44px 那一列居中，与名单序号 01 / 02 同列；标题从 56px 开始，与头像左缘对齐。
  - 搜索：名单页“名单簿”左边是放大镜按钮，点开后“名单簿”变成输入框、放大镜换成“X”，点“X”清空输入、失焦并收起；按 QQ 号（包含）或昵称（包含，忽略大小写）筛选，搜索时不显示人数。失焦时输入为空就收回成“名单簿”，Esc 清空并失焦。搜索只改页码、不换纸，所以输入法组字不会被打断；搜索中翻页照常有翻页动画，从成员页返回时回到该成员在搜索结果里的那一页。

### 多实例 Web Locks 槽位

为了避免同时打开过多页面后耗尽浏览器的同 origin 连接数，main.tsx 在挂载应用前调用 `acquireTabSlot()`。它用 Web Locks 给每个顶层页面占一个 `__app_tab__:<uuid>` 锁：先在短命的 guard 锁里 `navigator.locks.query()` 数已占用的槽位，再在临界区内真正拿到该页面的锁，然后才释放 guard。锁由浏览器持有到页面销毁，不需要 localStorage、心跳或超时清理。超过 5 个槽位时，新页面不挂载应用，只显示一张说明书式的线圈本：保留拓扑图标，正文下方用 TextLink“为什么会如此”翻到等高的连接限制说明页；两页都有同一条线圈、孔和下方压纸，纸页在 1600px 透视下绕上沿翻起；`pageBody` 里正面在 `translate3d(0, 0, 1px)`，空白背面在 `translate3d(0, 0, -1px) rotateX(180deg)`，两面都 `backface-visibility: hidden`。翻页拆成两阶段：先用 280ms 只做 3D 转向到 90°，到达 90° 时由 React 直接卸载正面内容，只剩空白纸背；之后再用 160ms 对空白纸背做 opacity 淡出。返回时先用 160ms 把空白背面从 100° 淡入到 90°，再恢复正面并用 280ms 转回 0°。可见内容期间 3D 纸页本身绝不改变 opacity。返回时同一动画反向播放，目标纸页从上方翻回来。超限页不建立任何 SSE 连接，并每秒重试占位；空出槽位后自动进入。iframe 不单独占槽，交给顶层窗口计数。

SSE 本身也在页面隐藏时断开，回到前台再重连；两层一起保证后台标签不会长期占用连接。

### 与公开页的边界

- 叙事性动效（CRT 换台、碎纸机、逐字文案）不进入后台管理操作的主路径。进入 `/admin` 时的换台属于频道切换，不属于管理操作。后台瀑布流里相片贴上来 / 撕下去和公开页同一套，它只跟着数据播，不挡任何操作，也不让操作等它。
- 后台的机械反馈本身必须是瞬时的：琴键在按下的同一帧切换面板，声音与动作同时发生；走纸、翻盖、LED 衰减只是附加在已完成状态上的质感，不阻塞点击、输入或提交。
- mutation 不等待任何动画；请求状态由 LED、按钮按下状态或打印输出直接表达。
- 公开页可以保留拍立得、大字号和叙事性动效；不要为了统一而把公开页做成控制台，也不要把后台做成普通卡片 UI。

## 已弃用组件

`src/web/components/deprecated/` 放不再使用、但造型或交互值得留着的组件。

- 不被任何页面引用；构建时不会进入 bundle。新页面不要引用它们，除非明确决定复用。
- 每个组件文件开头写清：原来在哪用、为什么弃用、被什么取代、原来的调用方式。
- 移进来时类名换成组件自己的前缀，不再借用原页面的类名，避免和原页面样式互相影响。
- 依赖的公共组件（`Slit`、`Popover`、`WhitePlasticButton` 等）改 API 时，这里的组件也要能通过 typecheck；改不动时可以删掉，删之前先问用户。
- 复用时把它移出 `deprecated/`，并在本节删掉对应条目。

当前收着的：

- `AdminLoginDrawer`：原 Behind 页的后台登录抽屉。高 56px 的铝灰面板，左刻 `ADMIN`，中间 132×32px 横杆拉手，右边一颗收起灭、拉开绿的小灯；托盘里是密码框 +“进入”，错误用 Popover 挂在密码框上方。拉开时 ✋ 从下方伸到拉手（380ms），停 160ms 变 ✊ 握住，抽屉滑出 360ms 时 ✊ 跟着下来，再松手淡出（180ms）；已拉开时点面板直接推回去。被 Navigator 的“A”按钮和 `/admin` 的门禁（`AccessPanel`）取代。

## 决策清单

新增交互、动画或声音前，按顺序问：

1. 它是否帮助理解状态？
2. 它是否延迟了用户输入？
3. 它是否有明确的叙事回报？
4. 有没有更简单的瞬时反馈？
5. 它是否值得长期维护？

如果答案不明确，选择瞬时状态或不做。

## 避免

- 为了“顺滑”给普通交互加 transition。
- 无意义的淡入淡出、悬浮位移、缩放和阴影动画。
- 把公开页做成通用 SaaS 卡片或玻璃拟态。
- 为了动效或声音引入新依赖；`motion` 和 `three` 不扩散到碎纸机以外。
- 使用音频文件或循环背景音。
- 让动画或声音阻塞点击、输入或页面切换。
