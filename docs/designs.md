# 设计原则

本文记录项目的交互、视觉与声音判断标准。公开页与后台共享“精确 / 有趣 / 克制”三条原则，但风格不同：公开页是纸质小刊物，后台是拟物控制台。文中数值以代码实现为准，代码变更时同步更新本文。

## 精确

直接操作要跟手。

- 鼠标悬停、点击、手指触摸的反馈立即出现，不等待动画。
- 状态变化优先使用瞬时切换，不用 transition 制造“顺滑感”。
- 颜色、边框、按压反馈默认瞬间完成。
- 加载和网络操作要给出明确状态，但不能用装饰动画拖延输入。

判断标准：用户做完动作后，界面应该在同一帧给出回应。

## 有趣

只有在有叙事价值的时刻才使用动画和声音。

例子：

- 切换频道时的 CRT 换台；
- 取消投稿时的碎纸机；
- 致命错误后的关闭荧幕效果；
- 关键弹层的转场。

这些效果是例外，不是默认配置。一个动画如果只是让页面“看起来更高级”，就不加。完整清单见“叙事时刻”。

## 克制

少即是多。

- 如非必要，不做装饰性动画。
- 如果瞬时状态已经足够，就不加动画。
- 如果没有比“精确”更好的方案，就不加动画。
- 尽可能不引入第三方动画库。
- 不为了“顺滑”给普通按钮、链接、表单加过渡。

一个交互只保留必要的反馈；能删就删，能瞬时就不渐变。

当前的 `motion` 与 `three` 是为碎纸机这一叙事时刻不得已引入的：`three` 负责碎纸条的 WebGL 场景，`motion` 只用了 `useReducedMotion`。两者只允许在碎纸机组件内使用，不扩散到其他组件，也不作为新增动效的理由。

## 叙事时刻

以下是已经批准的叙事时刻。新增一项前先过“决策清单”。

### CRT 换台

切换 `/explore`、`/behind`、`/admin` 频道，以及进入、离开取消投稿时触发（`ChannelTransition`）。

- 换台层持续 900ms：半透明黑屏、180×110 的灰度噪点和彩色马赛克每 55ms 重绘一次、扫描线、滚动亮带、两次白闪；最后 14% 淡出。
- 换台期间页面每帧随机抖动，位移为视口宽高的 30%–70%，并叠加 `contrast(1.08) saturate(1.15)`。900ms 结束时切到新频道并复位。
- 频道 OSD 显示 3000ms，例如 `CH. Explore`：左上角 64px、字重 900 的白字黑描边；宽度不超过 640px 时不显示。
- 切换完成后，一条白色余辉扫描线从视口 30–60vh 的随机位置向下扫过 30vh，持续 2400ms。
- 同时播放换台音效，见“声音”。

### 碎纸机

取消投稿页（`/explore/cancelSubmission`）用 `PaperShredder` 把相片缩略图碎掉。

- 页面出现 2000ms 后自动开始；也可以直接拖动纸张送入。
- 送纸速度为 35px/s，切成 30 条；碎纸条在 three.js 场景中落进浅仓，折叠堆叠在可见区域。没有 WebGL 时纸张照常送入，只是看不到出纸。
- 取消投稿请求在进入页面时就发出，不等动画；碎完后等待请求完成，再过 2000ms 回到 `/explore`。
- 马达和切纸声随马达启停，见“声音”。

### 致命错误 CRT

`FailureLayoutContainer` 收到错误后（来源：根组件渲染异常，或 `signal_critical_error`，例如公开页获取相册数据失败）：

- 等待 1000ms，原页面执行 550ms 的关屏：先压成一条亮线，再缩成一点，最高亮度为 50 倍，背景变黑。
- 再等 1500ms，错误页执行 4s 的开屏：先过曝闪动，再从黑场恢复。
- 错误页使用 guanzhi 8×8 点阵字体，带 0.15s 的闪烁和 1.6s 的 RGB 偏移文字阴影。完整字体下载期间，每秒多显示一个 `◼`（最多 7 个），字体加载失败时回退到原始字体地址，保证错误信息可见。

### 拉杆

Behind 页的后台入口是一根拉杆（`AdminPullHandle`）。

- 点击后 ✋ 在 100ms 内出现，用 380ms 移到拉杆处，停留 300ms 后变成 ✊，同时展开登录区（`Slit`）。
- 握住 260ms 后松手淡出，再过 120ms 回到可点击状态。整个过程约 1.06s，期间按钮为 `disabled` 且 `aria-busy`。
- 已展开时再次点击直接收起，不播放手部动画。

### 逐字文案

投稿剧本（`Submission`）的叙事文字逐字出现。

- 每个字间隔 42ms，每出现一个字播放一次逐字音效。
- 多个选项依次播放：后一个选项在前一个播完后，再等 420ms（10 个字的时间）开始。
- 首屏文案没有用户手势，浏览器还不能可靠地播放声音，因此首屏的文案和选项全部瞬时显示。
- 删除线等剧本节点可以单独触发一次音效作为节拍。

### 弹层转场

确认投票等关键弹层使用 `DialogLayout`。

- 进入：遮罩在 800ms 内加深到 `rgba(0, 0, 0, 0.182)`；横贯屏幕的白色版面同时从左侧滑入，边缘带 20px 渐隐；内容延迟 300ms 后用 500ms 从左侧 1em 处淡入。
- 退出：白色版面在 800ms 内向右滑出，内容在 500ms 内向右 1em 淡出。
- 组件按 1100ms 切换状态；打开期间禁止页面滚动。

## 声音

声音的用意类似 Nintendo Switch 的系统音效：

- 有趣：耳朵上的愉悦感，让按键、换台、出字这些动作有“质感”。
- 精确：声音和动作在同一时刻发生，是即时反馈，不是背景音乐，也不延迟操作。

### 合成方式

- 全部用 Web Audio 实时合成，没有音频文件，也不引入音频依赖。
- 素材只有振荡器（三角波、方波、锯齿波）、白噪声缓冲和滤波器；每个音效都由短包络塑形，用完即停。
- 音效与动作绑定，不做循环背景音。唯一的持续声是碎纸机马达，它只在马达运转时响。

| 音效 | 位置 | 构成 |
| --- | --- | --- |
| 换台 | `utils/crt-audio.ts` | 118→42Hz 三角波“噗”（240ms）+ 2100→740Hz 方波 click（40ms）+ 1650Hz 带通白噪声“沙沙”，在 860ms 处截断 |
| 逐字 | `utils/text-audio.ts` | 方波短音，音高为 540Hz 加上按字符计算的偏移（0–359Hz）和 0–45Hz 随机抖动，经 2400Hz 低通，34ms 衰减 |
| 琴键按下 | `utils/mechanical-key-audio.ts` | 155→78Hz 三角波键体 + 2300→980Hz 金属 click + 1250Hz 带通噪声，约 100ms |
| 琴键回弹 | `utils/mechanical-key-audio.ts` | 延迟 45ms；310→520Hz 三角波 + 1650→2700Hz click + 1800Hz 高通噪声，比按下更轻、更高 |
| 盖板弹出 | `utils/mechanical-key-audio.ts` | 3200→1400Hz 方波卡扣脆响 + 2400Hz 高通噪声；60ms 后 240→120Hz 三角波撞到限位 + 900Hz 带通噪声 + 520→760Hz 正弦弹簧余震，约 140ms。只在打开时响 |
| 发射按钮“dang” | `utils/mechanical-key-audio.ts` | 150→82Hz 三角波撞底 + 3000Hz 带通噪声瞬态 + 660 / 1657 / 2433Hz 非谐波正弦分音，分别衰减 600 / 380 / 220ms。指针按下时立即发声，键盘触发在 click 时发声 |
| Spinner 滴答 | `components/Spinner` | 每走一格一次，带通噪声在 2450Hz 和 1750Hz 之间交替，30ms |
| 碎纸机 | `PaperShredder` | 92Hz 锯齿波马达经 380Hz 低通 + 循环白噪声经带通；纸被咬住时带通频率在 1000–2200Hz 间游走 |

Behind 页的 Zelda 风格横幅（`ZeldaQuestBanner`）也是合成音，目前只作为试验入口存在。

### 预热时机

- 浏览器只允许在用户手势之后启动音频。`PublicRoot` 在首次 `pointerdown` 或 `keydown`（capture，只触发一次）时预热换台和逐字两个音频上下文。
- Spinner 在需要出声时监听 `pointerdown` / `keydown` 来恢复自己的音频上下文，卸载时关闭。
- 碎纸机的马达在首次需要出声时才创建。
- 正因为首屏没有手势，投稿剧本的第一面整体瞬时显示，不播放逐字音效。

### 降级规则

- 没有 `AudioContext`、创建失败或播放抛错时，一律静默，不影响动画和操作。
- 逐字音效和 Spinner 滴答在音频上下文不是 `running` 状态时直接跳过，不排队补播，避免恢复后一连串集中爆发。
- 换台、琴键、盖板、发射按钮这类单次音效在 `suspended` 状态下会先尝试恢复，恢复后再播放；恢复失败就放弃。
- 组件可以关闭声音：Spinner 的 `audioVolume={0}`、碎纸机的 `sound={false}`。

### 音量层次

从响到轻：

1. 换台：主增益 1.28，“噗”的峰值 0.62。它标志频道切换，是最响的一声。
2. 发射按钮与盖板：“dang”撞底峰值 0.45，金属分音 0.2 / 0.08 / 0.04；盖板撞限位峰值 0.32。只在缩略图重建这一次性操作时出现。
3. 琴键：按下时键体峰值 0.42；45ms 后旧键回弹，主增益 0.88，峰值 0.15。
4. Spinner 滴答：`audioVolume` 乘以 0.55，常用的 0.8 对应峰值约 0.44，但只持续 30ms。
5. 碎纸机马达：持续输出 0.16，启动时间常数 30ms，停止时间常数 90ms。持续声必须压低。
6. 逐字：峰值 0.09，34ms。它出现得最频繁，所以最轻。

原则：越频繁、越持续的声音越轻；越少见、越有转折意义的声音越响。

## 查看大图

- 保持点击缩略图打开、点击大图或背景关闭；也可用 Escape 关闭。
- 保持原适屏尺寸和居中规则，以及图片 382ms、背景遮罩 618ms 的转场时长；转场只改变 transform 和 opacity，不逐帧修改尺寸或位置。
- 双指捏合及 trackpad 捏合以手势中心缩放，范围是适屏大小的 1–5 倍。支持 Chromium/Firefox 的 ctrl-wheel 和 Safari 的原生 gesture 事件，不缩放整个网页。
- 放大后单指或鼠标拖动平移，trackpad 双指滚动也可平移；平移约束在图片边界内。双指操作结束或只剩一指时，不把松指误判为关闭。
- 未放大时，单指向上或向下拖动超过 100px，且纵向位移大于横向位移，松手关闭；不足阈值则立即复位。点击允许 8px 内的触摸抖动。
- 缩略图点击回调内立即下载 optimized 字节，不排队等待入场动画。图片和背景入场动画全部结束前，只显示缩略图，不解码或挂载 optimized 图片；结束后异步解码并直接插入已解码的图片元素。
- 关闭或切换相片时取消旧请求，忽略迟到的解码结果；退出完成后释放对象 URL 和事件监听。加载失败仍保留缩略图并提供重试。
- 遵循减少动态效果偏好时，转场时长为 0；不新增运行时依赖。

## 后台相片投票磁粒

- 仅 `/admin` 的 PhotoBox 显示投票磁粒；复用 AdminPool 的 `vote_records`，按相片归集，票数与记录使用同一份数据，不新增 API 或公开投票人信息。
- 蓝色 `rgba(48, 103, 133, 1)` 表示 1 票，红色 `#ba1616` 表示 5 票。每 5 票换成一颗红色，余数为蓝色；排列先蓝后红，高面额靠右，6 票为「蓝 红」，13 票为「蓝 蓝 蓝 红 红」，0 票不生成磁粒。
- 磁粒直径 16px、间距 6px，贴在相片右上方、距边缘 8px，满行后换行。空间不足时整体等比缩小；极短或极窄图片的留白不超过图片短边的 1/4。磁粒和“0 票”入口都在 `cover-area` 内，绝不进入 `bottom-area`，不改变瀑布流卡片尺寸。
- 相片磁粒使用 `translate()` 添加 X 轴 1–2px、Y 轴 2–3px 的正向随机偏移，每颗磁粒在首次挂载时生成并由 `useRef` 缓存；普通重渲染及切换相片排序不重新生成。使用面额与该面额内序号作为稳定 key；极小图片留白不足 3px 时缩小偏移，避免越出图片区。图例磁粒不偏移。
- 每个展开且非空的相册在管理 `.panel` 与瀑布流之间显示同款磁粒图例，以及“按投稿时间顺序 / 按获票数顺序”和“升序 / 降序”两个选单。默认投稿时间升序，同值按相片 ID 升序保持稳定。
- 图例排序仅作用于当前页面的相片数组副本，不修改 AdminPool、不调用 mutation，也不保存到服务端。每个相册独立保存选项；瀑布流按输入顺序重新排布且保持相片组件挂载，不重置磁粒偏移。公开页仍使用原有位置保留规则。
- 点击磁粒组或“0 票”入口打开只读投票记录，显示总票数、投票人昵称、QQ 和投票时间，按时间从新到旧排列。找不到成员时仍保留记录与票数，并显示成员 ID。
- 记录列表内部滚动，支持键盘打开、Escape 或点击外部关闭；磁粒点击不触发相片编辑，弹层内部操作也不冒泡到卡片。沿用现有 Popover，不新增动效或依赖。

## 公开页的 UI 风格

回顾 `src/web/` 的公开页（`/explore`、`/behind`，不包含后台），整体风格可以概括为：

**纸质独立刊物 + 早期日式个人网站 + 早期 OS X 式轻拟物。**

它不是现代 SaaS 或通用相册模板，而是一个有性格的私人活动站点。具体表现为：

- **底色与背景**：全局底色是低饱和的蓝灰 `hsl(217deg 20% 80% / 50%)`，叠加 1px 宽的竖向细条纹（白 `rgba(255, 255, 255, 0.7)` 与灰 `rgba(220, 220, 220, 0.4)` 交替），即早期 OS X 的 pinstripe。iOS / iPadOS 去掉条纹，只留纯色。“纸”体现在白色的相片卡片和横贯版面的白色弹层上，而不是底色。
- **Behind 页**：白底、正文 `#252525`；深色模式下底色为 `#1b2027`。
- **色彩**：低饱和蓝绿主色 `#306785`，少量红心点缀。颜色数量少，对比克制，主要靠留白和层次，而不是高饱和配色。
- **排版**：大留白、窄内容列、居中叙事、细分割线、超大标题。照片以错落卡片/瀑布流的方式排列，有编辑排版感，不是整齐划一的网格。
- **相片卡片**：白色拍立得式卡片、小圆角、柔和的多层阴影和细边框；圆形头像压在卡片边缘；每张照片带描述和心形投票入口。
- **组件质感**：按钮有轻微拟物的高光、渐变、内阴影和按压下沉；圆形环按钮、胶囊按钮、细线输入框。拟物是轻的，不追求写实材质。
- **文字**：正文以系统无衬线字体为主，复古感来自排版和组件，而不是全局使用像素字体。文案口语化、朋友式，带轻微戏谑或日式翻译腔；关键提示使用大字号和横贯版面的标题。
- **特殊时刻**：CRT 换台、碎纸机、致命错误 CRT、拉杆、逐字文案、弹层转场，详见“叙事时刻”。
- **动效**：数量少，基本只服务于叙事和状态转折。普通悬停、点击和状态切换依赖瞬时反馈。

这套风格的核心不是“复古元素堆叠”，而是：像一本有人味的纸质小刊物，而不是一个产品化后台。

## 后台的 UI 风格

`/admin` 是**拟物控制台**：把管理工作做成一台有按键、指示灯、显示屏和打印机的操作台。它对应的是“有趣”——管理本身也可以好玩。

- **基础**：所见即所得编辑器，复用公开页的 Navigator、照片卡片、圆角、pinstripe 底色和轻拟物语言，管理者看到的就是公开页的样子。
- **琴键**：面板切换是一排录音机式琴键（`role="radiogroup"`）。按下的键立即切换面板，旧键同时弹起，并配按下声和 45ms 后的回弹声；方向键可以切换。大屏时所有面板平铺，琴键只负责定位。
- **指示灯**：LED 有常亮和脉冲两种模式。常亮模式切换用 150ms；脉冲先保持高亮，再按 RC 放电曲线衰减。
- **热敏打印机**：只有出错才吐纸。纸是平的，从槽口直接伸出，不做弯曲和透视；新的一行贴着槽口，用 240ms、6 级阶梯推进，把旧行往下推，最多 14 行。
- **玻璃盖**：危险操作罩在玻璃盖下。点一次盖板就弹开（340ms 回弹曲线，`rotateX(-108deg)`）并配盖板弹出声，再点一次合上；开盖后红色按钮才可按，按下时配“dang”声。按下的同一帧“剩余项目”数码管就显示总数，不等第一张图处理完；重建结束后盖板自动合上。
- **按钮与材质**：银白塑料按钮、内凹面板、磨砂指扣，比公开页更“硬件”，但仍然不追求照片级写实。

### 与公开页的边界

- 叙事性动效（CRT 换台、碎纸机、逐字文案、拉杆）不进入后台管理操作的主路径。进入 `/admin` 时的换台属于频道切换，不属于管理操作。
- 后台的机械反馈本身必须是瞬时的：琴键在按下的同一帧切换面板，声音与动作同时发生；走纸、翻盖、LED 衰减只是附加在已完成状态上的质感，不阻塞点击、输入或提交。
- mutation 不等待任何动画；请求状态由 LED、按钮按下状态或打印输出直接表达。
- 公开页可以保留拍立得、大字号和叙事性动效；不要为了统一而把公开页做成控制台，也不要把后台做成普通卡片 UI。

## 决策清单

新增交互、动画或声音前，按顺序问：

1. 它是否帮助理解状态？
2. 它是否延迟了用户输入？
3. 它是否有明确的叙事回报？
4. 有没有更简单的瞬时反馈？
5. 它是否值得长期维护？

如果答案不明确，选择瞬时状态或不做。

## 避免

- 为了“顺滑”给普通交互加 transition。
- 无意义的淡入淡出、悬浮位移、缩放和阴影动画。
- 把公开页做成通用 SaaS 卡片或玻璃拟态。
- 为了动效或声音引入新依赖；`motion` 和 `three` 不扩散到碎纸机以外。
- 使用音频文件或循环背景音。
- 让动画或声音阻塞点击、输入或页面切换。
