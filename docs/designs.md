# 设计原则

本文记录项目的交互与视觉判断标准。它主要约束公开页；后台是另一套更工具化的界面，不直接套用公开页风格。

## 精确

直接操作要跟手。

- 鼠标悬停、点击、手指触摸的反馈立即出现，不等待动画。
- 状态变化优先使用瞬时切换，不用 transition 制造“顺滑感”。
- 颜色、边框、按压反馈默认瞬间完成。
- 加载和网络操作要给出明确状态，但不能用装饰动画拖延输入。

判断标准：用户做完动作后，界面应该在同一帧给出回应。

## 有趣

只有在有叙事价值的时刻才使用动画。

例子：

- 删除相片后的灭霸消散效果；
- 致命错误后的关闭荧幕效果；
- 关键弹层的转场。

这些效果是例外，不是默认配置。一个动画如果只是让页面“看起来更高级”，就不加。

## 克制

少即是多。

- 不做装饰性动画。
- 如果瞬时状态已经足够，就不加动画。
- 如果没有比“精确”更好的方案，就不加。
- 不为动效引入第三方动画库。
- 不为了“顺滑”给普通按钮、链接、表单加过渡。

一个交互只保留必要的反馈；能删就删，能瞬时就不渐变。

## 公开页的 UI 风格

回顾 `src/web/` 的公开相册页（`/`，不包含后台），整体风格可以概括为：

**纸质独立刊物 + 早期日式个人网站 + 早期 OS X 式轻拟物。**

它不是现代 SaaS 或通用相册模板，而是一个有性格的私人活动站点。具体表现为：

- **色彩**：暖灰纸张底色、低饱和蓝绿主色 `#306785`、少量红心点缀。颜色数量少，对比克制，主要靠留白和层次，而不是高饱和配色。
- **排版**：大留白、窄内容列、居中叙事、细分割线、超大标题。照片以错落卡片/瀑布流的方式排列，有编辑排版感，不是整齐划一的网格。
- **相片卡片**：白色拍立得式卡片、小圆角、柔和的多层阴影和细边框；圆形头像压在卡片边缘；每张照片带描述和心形投票入口。
- **组件质感**：按钮有轻微拟物的高光、渐变、内阴影和按压下沉；圆形环按钮、胶囊按钮、细线输入框。拟物是轻的，不追求写实材质。
- **文字**：正文以系统无衬线字体为主，复古感来自排版和组件，而不是全局使用像素字体。文案口语化、朋友式，带轻微戏谑或日式翻译腔；关键提示使用大字号和横贯版面的标题，叙事文字有逐字出现的效果。
- **特殊时刻**：错误页使用点阵字体和 CRT 关闭/开启效果；删除相片使用灭霸消散；重要弹层使用大字号、横贯屏幕的白色版面和滑入转场。
- **动效**：数量少，基本只服务于叙事和状态转折。普通悬停、点击和状态切换依赖瞬时反馈。

这套风格的核心不是“复古元素堆叠”，而是：像一本有人味的纸质小刊物，而不是一个产品化后台。

### 与后台的边界

- 公开页可以保留拟物、拍立得、大字号和叙事性动效。
- 新 `/admin` 是所见即所得编辑器，明确例外：复用公开页的 Navigator、照片卡片、圆角、纸张纹理和轻拟物语言。
- 新 `/admin` 的管理控件仍保持精确、紧凑、瞬时反馈；不要把公开页的叙事性动效复制进管理操作。
- 不要为了统一而把公开页做成普通卡片 UI。

## 决策清单

新增交互或动画前，按顺序问：

1. 这个动画是否帮助理解状态？
2. 它是否延迟了用户输入？
3. 它是否有明确的叙事回报？
4. 有没有更简单的瞬时反馈？
5. 它是否值得长期维护？

如果答案不明确，选择瞬时状态或不做。

## 避免

- 为了“顺滑”给普通交互加 transition。
- 无意义的淡入淡出、悬浮位移、缩放和阴影动画。
- 把公开页做成通用 SaaS 卡片或玻璃拟态。
- 为了动效引入新依赖。
- 让动画阻塞点击、输入或页面切换。
